# 前端改造设计 - 总体方案

## 📊 现有前端项目概览

### 1. 平台端管理系统（et_plat_admin）
- **技术栈**: Vue 2.6.10 + Element UI 2.15.6 + Vue Router + Vuex
- **构建工具**: Vue CLI 3.5.3
- **用途**: 平台管理员使用，管理商家、商品审核、询价管理等

### 2. 商家端管理系统（et_mer_admin）
- **技术栈**: Vue 2.6.10 + Element UI 2.15.6 + Vue Router + Vuex
- **构建工具**: Vue CLI 3.5.3
- **用途**: 商家使用，管理商品、查看翻译状态等

### 3. PC端商城（et_pc）
- **技术栈**: Nuxt.js 2.15.8 + Vue 2.6.14 + Element UI 2.15.6 + vue-i18n 8.26.7
- **特点**: SSR服务端渲染，已集成vue-i18n多语言支持
- **用途**: C端用户浏览商品、提交询价

### 4. 移动端商城（et_uniapp）
- **技术栈**: uni-app（跨平台框架）
- **特点**: 支持H5、小程序、APP
- **用途**: C端移动端用户浏览商品、提交询价

## 🔧 改造原则

### 1. 基于现有代码改造
- 保留现有项目结构和代码风格
- 复用现有组件和工具函数
- 不重新搭建项目，在现有基础上修改

### 2. 多语言支持
- **PC端**: 已有vue-i18n，扩展语言包（增加俄语、阿拉伯语）
- **移动端**: 需要集成vue-i18n或uni-app的国际化方案
- **管理端**: 不需要多语言，永远显示中文

### 3. 组件复用
- 复用现有的表格、表单、弹窗等组件
- 扩展现有组件以支持新功能
- 保持UI风格一致

### 4. 路由管理
- 删除不需要的路由
- 新增需要的路由
- 调整菜单结构

### 5. API接口对接
- 使用axios统一管理API请求
- 根据API接口设计文档对接后端接口
- 处理多语言请求头（Accept-Language）

## 🌐 多语言实现方案

### PC端（et_pc）- 已有vue-i18n

**现状**: 已集成vue-i18n 8.26.7

**改造方案**:
1. 扩展语言包（增加俄语ru、阿拉伯语ar）
2. 语言切换器组件（下拉选择：中文/English/Русский/العربية）
3. 语言持久化（localStorage存储用户选择）
4. API请求头（axios拦截器自动添加Accept-Language）
5. 阿拉伯语RTL支持（右到左布局）

### 移动端（et_uniapp）

**现状**: 未集成国际化方案

**改造方案**:
1. 集成uni-i18n或vue-i18n
2. 创建语言包文件（zh/en/ru/ar）
3. 语言切换器组件
4. 语言持久化（uni.setStorageSync）
5. API请求头（请求拦截器添加Accept-Language）
6. 阿拉伯语RTL支持

## 💡 技术要点

### 1. 多语言切换
- 使用vue-i18n管理语言包
- 语言切换后刷新页面数据
- API请求自动携带语言标识

### 2. 阿拉伯语RTL支持
- 使用CSS的direction: rtl
- 调整布局和样式
- 图标和箭头方向反转

### 3. 图片上传
- 复用现有的图片上传组件
- 支持多图上传（轮播图、详情图）
- 图片预览和删除

### 4. 翻译状态显示
- 使用进度条显示翻译进度
- 不同状态使用不同颜色标识
- 翻译失败显示错误信息

### 5. 询价表单
- 表单验证（邮箱、手机号格式）
- 支持单商品询价和批量询价
- 游客和登录用户都可以提交

## ✅ 设计原则总结

1. **最小改动原则** - 尽量复用现有代码，减少改动范围
2. **渐进式改造** - 先删除不需要的功能，再新增需要的功能
3. **保持一致性** - 保持现有的代码风格和UI风格
4. **可维护性** - 代码结构清晰，注释完整
5. **可扩展性** - 预留扩展空间，方便后续功能迭代
